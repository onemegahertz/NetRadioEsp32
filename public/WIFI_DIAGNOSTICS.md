# 🔧 Диагностика WiFi проблем

## Проблема: NetRadio подключается к WiFi, но не получает IP адрес

### ✅ Что исправлено в новой версии:

1. **Добавлена проверка получения IP адреса**
   - Проверяется что IP не равен 0.0.0.0
   - Если IP не получен - автоматический переход в AP mode

2. **Увеличено время ожидания**
   - Было: 20 попыток (10 секунд)
   - Стало: 30 попыток (15 секунд)
   - Добавлена задержка 1000мс после подключения

3. **Подробная диагностика в Serial Monitor**
   - Показывается SSID сети
   - Показывается статус подключения
   - Показывается RSSI (сила сигнала)
   - Показывается полученный IP адрес

4. **Отображение на экране**
   - Показывается название WiFi сети
   - Показывается статус подключения
   - Показывается IP адрес
   - Показываются ошибки

## 📋 Как использовать новую диагностику:

### Шаг 1: Загрузите обновлённый скетч

Скачайте `NetRadio_v2_ESP32.ino` и загрузите в Arduino IDE.

### Шаг 2: Откройте Serial Monitor

- Скорость: 115200 baud
- Наблюдайте за процессом подключения

### Шаг 3: Проверьте сообщения

**Нормальное подключение:**
```
[WiFi] Connecting to: MyHomeNetwork
................
[WiFi] Connected! SSID: MyHomeNetwork
[WiFi] IP: 192.168.1.100
[WiFi] RSSI: -65 dBm
```

**Ошибка подключения:**
```
[WiFi] Connecting to: MyHomeNetwork
..............................
[WiFi] ERROR: Connection failed!
[WiFi] Status: 1
[WiFi] Fallback to AP mode, IP: 192.168.4.1
```

**Подключение без IP:**
```
[WiFi] Connecting to: MyHomeNetwork
................
[WiFi] ERROR: Connected but no IP assigned!
[WiFi] Fallback to AP mode, IP: 192.168.4.1
```

## 🔍 Возможные причины проблем:

### 1. Неправильный пароль WiFi

**Симптомы:**
```
[WiFi] ERROR: Connection failed!
[WiFi] Status: 1
```

**Решение:**
- Проверьте SSID и пароль в веб-интерфейсе
- Убедитесь что пароль введён правильно (учитывайте регистр)
- Попробуйте пересохранить WiFi настройки

### 2. WiFi сеть не найдена

**Симптомы:**
```
[WiFi] Connecting to: MyNetwork
..............................
[WiFi] ERROR: Connection failed!
[WiFi] Status: 1
```

**Решение:**
- Проверьте что сеть доступна
- Убедитесь что ESP32 в зоне покрытия
- Проверьте что сеть 2.4GHz (не 5GHz)

### 3. DHCP не работает (нет IP адреса)

**Симптомы:**
```
[WiFi] Connected! SSID: MyNetwork
[WiFi] ERROR: Connected but no IP assigned!
```

**Решение:**
- Перезагрузите роутер
- Проверьте настройки DHCP на роутере
- Попробуйте статический IP (см. ниже)

### 4. Слабый сигнал WiFi

**Симптомы:**
```
[WiFi] RSSI: -85 dBm  (очень слабый сигнал)
```

**Решение:**
- Переместите ESP32 ближе к роутеру
- Уберите препятствия между ESP32 и роутером
- Используйте WiFi repeater

### 5. Роутер блокирует устройство

**Симптомы:**
- Подключение проходит, но нет интернета
- IP получен, но нет доступа к веб-интерфейсу

**Решение:**
- Проверьте настройки роутера
- Добавьте ESP32 в белый список MAC-адресов
- Отключите фильтрацию MAC-адресов

## 🛠️ Расширенная диагностика:

### Проверка силы сигнала (RSSI)

Добавьте в скетч после подключения WiFi:
```cpp
Serial.printf("[WiFi] RSSI: %d dBm\n", WiFi.RSSI());
```

**Значения RSSI:**
- -30 до -50 dBm: Отличный сигнал
- -50 до -70 dBm: Хороший сигнал
- -70 до -80 dBm: Средний сигнал
- -80 до -90 dBm: Слабый сигнал
- Менее -90 dBm: Очень слабый сигнал

### Проверка статуса WiFi

Добавьте в скетч:
```cpp
Serial.printf("[WiFi] Status: %d\n", WiFi.status());
```

**Значения статуса:**
- 0: WL_IDLE_STATUS - ожидание
- 1: WL_NO_SSID_AVAIL - сеть не найдена
- 2: WL_SCAN_COMPLETED - сканирование завершено
- 3: WL_CONNECTED - подключено
- 4: WL_CONNECT_FAILED - ошибка подключения
- 5: WL_CONNECTION_LOST - соединение потеряно
- 6: WL_DISCONNECTED - отключено

### Проверка DNS

Добавьте в скетч:
```cpp
Serial.printf("[WiFi] DNS: %s\n", WiFi.dnsIP().toString().c_str());
```

## 🔧 Ручная перепрошивка WiFi настроек:

Если WiFi не работает, можно очистить настройки:

### Метод 1: Через веб-интерфейс
1. Подключитесь к AP mode (NetRadio/netradio123)
2. Откройте http://192.168.4.1
3. Введите новые WiFi настройки
4. Нажмите "Save WiFi"

### Метод 2: Через Serial Monitor
Добавьте в скетч команду очистки:
```cpp
// Добавьте в setup() перед WiFi подключением:
if (Serial.available()) {
  String cmd = Serial.readStringUntil('\n');
  if (cmd == "CLEAR_WIFI") {
    prefs.begin("netradio", false);
    prefs.clear();
    prefs.end();
    Serial.println("[WiFi] Settings cleared!");
    ESP.restart();
  }
}
```

Затем в Serial Monitor введите: `CLEAR_WIFI`

### Метод 3: Полная очистка Flash
1. В Arduino IDE: Tools → Erase All Flash Before Sketch Upload → Enabled
2. Загрузите скетч заново
3. Настройте WiFi через веб-интерфейс

## 📡 Альтернативные решения:

### 1. Статический IP адрес

Если DHCP не работает, используйте статический IP:

```cpp
IPAddress local_IP(192, 168, 1, 200);
IPAddress gateway(192, 168, 1, 1);
IPAddress subnet(255, 255, 255, 0);
IPAddress primaryDNS(8, 8, 8, 8);
IPAddress secondaryDNS(8, 8, 4, 4);

if (!WiFi.config(local_IP, gateway, subnet, primaryDNS, secondaryDNS)) {
  Serial.println("[WiFi] STA Failed to configure");
}

WiFi.begin(ssid.c_str(), pass.c_str());
```

### 2. Использование другого канала WiFi

Некоторые роутеры используют каналы, которые ESP32 не поддерживает:
- Поддерживаемые каналы: 1-13 (2.4GHz)
- Измените канал роутера на 1, 6 или 11

### 3. Отключение WPS

Некоторые роутеры с WPS могут вызывать проблемы:
- Отключите WPS в настройках роутера

### 4. Изменение режима WiFi роутера

Измените режим с "Auto" на "802.11n only" или "802.11g only"

2. Попробуйте другой ESP32

5. Используйте более короткие провода
6. Попробуйте другую версию ESP32 core (2.0.11 или 2.0.14)
